The file URL ending in .jpg is almost certainly a renamed GIF or animated WebP file. Modern web browsers ignore file extensions and read the internal binary header of the file to decide how to render it.
(Note: The direct image URL you shared could not be fetched directly by my browsing tool, so this breakdown is based on standard CDN behavior and the visual frames from your screenshots).

Why It Moves on the Website

• Header Sniffing: When Elementa Games uploaded the animation to their CDN (s.elementagames.com), their CMS or upload script likely appended .jpg as a default extension even though the raw file is actually a GIF or WebP. Chrome and other browsers check the actual Content-Type header or file signature (GIF89a or RIFF...WEBP) and play the animation normally.
• Why Saving It Breaks or Looks Strange: If you right-click and save that file to your computer, Windows or your local image viewer trusts the .jpg extension rather than inspecting the file header. As a result, it either opens only the first static frame or throws a file corruption error.

How to Check and Fix the File

• Verify in Chrome DevTools: Press F12 on the news page, go to the Network tab, filter by Img, and click on 2740547ff367403112d1e43ea900e4c6.jpg. Under the Headers tab, look at Content-Type—it will likely say image/gif or image/webp.
• Rename the Extension: After saving the .jpg file to your PC, manually rename the extension to .gif or .webp (matching what you saw in DevTools). Once renamed, your local media players, Discord, and editors will recognize and play the full animation properly.

To handle mislabeled media URLs automatically when scraping, inspect the HTTP response headers or the raw binary magic bytes instead of trusting the file extension in the URL.
CDNs frequently serve GIF or WebP files under .jpg links, which can cause Discord embeds or local parsers to render only a static frame if you rely on the URL string.

1. Detect the True Format in Python

You can check the Content-Type header first, and fall back to reading the first few bytes (magic numbers) of the downloaded content to determine the real extension:
python
import requests

url = "https://elementagames.com"
response = requests.get(url, stream=True)
data = response.content

def get_true_extension(content_type: str, raw_bytes: bytes) -> str:
    # 1. Check magic bytes (most reliable)
    if raw_bytes.startswith(b"GIF87a") or raw_bytes.startswith(b"GIF89a"):
        return ".gif"
    if raw_bytes.startswith(b"RIFF") and raw_bytes[8:12] == b"WEBP":
        return ".webp"
    if raw_bytes.startswith(b"\x89PNG\r\n\x1a\n"):
        return ".png"
    if raw_bytes.startswith(b"\xff\xd8\xff"):
        return ".jpg"

    # 2. Fallback to Content-Type header
    if "gif" in content_type:
        return ".gif"
    if "webp" in content_type:
        return ".webp"
    return ".jpg"

ext = get_true_extension(response.headers.get("Content-Type", ""), data)
print(f"Detected real format: {ext}")
Use code with caution.

2. Handling Animated WebP vs. GIF for Discord

• Renamed .gif files: Once you save or upload the byte stream with a .gif filename (for example, via discord.File(io.BytesIO(data), filename="image.gif")), Discord will automatically animate it in embeds and messages.
• Animated .webp files: Discord does not always animate .webp files reliably when passed via external embed URLs or certain upload methods.
